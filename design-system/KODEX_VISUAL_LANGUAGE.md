# KODEX−∞ VISUAL LANGUAGE

Status: `CANONICAL DESIGN DIRECTION / V0.1`

## 1. Visual thesis

KODEX should look like an unknown cultural-computational instrument whose visual beauty emerges from meaningful structure.

It combines:

```text
EDITORIAL PRECISION
+ LIVING ORGANISMS
+ ARCHIVAL SYSTEMS
+ NEO-ANCESTRAL RESTRAINT
+ IMPOSSIBLE SPATIAL LOGIC
+ EVIDENCE-AWARE INFORMATION DESIGN
```

## 2. Composition

Primary heuristic for immersive scenes:

```text
75% world / artwork
15% narrative
7% navigation
3% metadata
```

Use this as a priority model, not a rigid measurement.

### Required hierarchy

1. one dominant visual question or organism;
2. one clear narrative statement;
3. one primary action;
4. inspectable sources and controls;
5. secondary metadata only when useful.

## 3. Spatial principles

- fullscreen or deliberately bounded canvas;
- high negative space around the protagonist;
- asymmetric editorial balance when it improves hierarchy;
- dense information appears in controlled regions, not uniformly;
- a rail, dossier or annotation zone may stabilize living artwork;
- mobile is recomposed, not compressed desktop;
- safe-area insets are respected.

## 4. World states

### `−∞ / OBSIDIAN`

- near-black field;
- incomplete edges;
- fragmented relations;
- restrained signal color;
- compressed spatial hierarchy;
- no assumption of evil, failure or low worth.

### `ACTIVE PATH`

- scene-specific accent;
- contrast between stable interface and living artwork;
- limited simultaneous signals;
- provenance remains accessible.

### `HEART`

- warm red as orientation and life;
- central pulse without fake ECG;
- clean perimeter and visible exit;
- amplitude adapts to motion preference.

### `RETURN / +∞`

- open white field;
- pure spectral color;
- less visual contamination;
- increased spacing;
- path relations become legible;
- artifact and sources emerge from prior memory.

## 5. Color system

Color roles:

```yaml
obsidian:
  role: unresolved field / entry

bone_white:
  role: readable structure on dark field

open_white:
  role: Return and integration

living_red:
  role: threshold, heart, active orientation

violet:
  role: observation, memory, ambiguity

acid_green:
  role: preserved organism, growth or activation

cyan:
  role: signal, relation or live technical state when grounded

orange:
  role: machine, transformation or controlled rupture

magenta:
  role: cosmology, expanded relation or speculative field
```

Rules:

- essential meaning never depends on color alone;
- no rainbow gradient merely to signal spirituality;
- spectral color at Return should be generated from path relations where possible;
- avoid using more than two simultaneous signal colors without a legend and reason;
- cultural colors require contextual review.

## 6. Typography

KODEX typography should create contrast between:

- monumental declaration;
- readable editorial explanation;
- precise metadata;
- code or system labels.

Rules:

- body text remains highly readable;
- technical or mono typography is used sparingly;
- metadata does not become microscopic decoration;
- type is stable while artwork moves;
- continuous text animation is prohibited;
- line length and contrast take priority over mood;
- all fonts require redistribution or web-use rights.

Recommended role system:

```text
DISPLAY / ritual declaration
EDITORIAL / long-form reading
INTERFACE / controls and navigation
MONO / code, source IDs and real system telemetry
```

## 9. Image treatment

Allowed treatments when semantically or atmospherically justified:

- controlled dither;
- bitmap threshold;
- restrained CRT scan;
- short temporal feedback;
- chromatic separation;
- thermal mapping when mapped to actual value or declared treatment;
- halftone and print texture;
- transparent line rendering;
- spectral decomposition;
- archival degradation representing real version/loss state.

Avoid permanent glitch and texture applied uniformly to all material.

## 10. Interface chrome

Chrome should be minimal and persistent:

- KODEX mark;
- node/scene name;
- previous, next and index;
- source/method access;
- sound and motion controls;
- safe exit;
- optional progress.

Chrome must not compete with artwork.

## 11. Information density

Scene density is functional:

- Threshold: low-to-medium, invitation and orientation;
- Prologue: medium, reading grammar;
- Descent: narrowing and selective detail;
- Archive: high but structured and filterable;
- Machine: medium-high with visible transformations;
- Heart: low, stable and calm;
- Cosmology: high relational density with progressive reveal;
- Return: initially low, then path artifact and source synthesis.

## 12. Reference-use protocol

For each visual reference:

1. identify creator and source;
2. identify structural principles;
3. identify distinctive expression that must not be copied;
4. derive a KODEX question and corpus;
5. choose a different composition, palette and symbol system;
6. document the transformation.

## 13. Mobile composition

At 390×844 and 412×915:

- protagonist remains visible without scroll;
- headline is not clipped;
- CTA and exit remain visible;
- metadata becomes an overlay or controlled rail;
- touch targets remain usable;
- artwork does not collapse into a small card;
- lower safe area is respected;
- reduced-motion fallback looks intentionally designed.

## 14. Visual definition of done

A scene passes when:

- the question is visually obvious;
- the protagonist is unique to the scene;
- data and atmosphere are distinguishable;
- typography remains readable;
- controls are stable;
- no unexplained decorative telemetry exists;
- mobile and desktop feel composed;
- the scene belongs unmistakably to KODEX without copying a reference.
