# KODEX−∞ Visual Atlas Mission

The Atlas is a maintained decision system that helps any agent translate a
reference, sketch or narrative intention into an implementable KODEX recipe.
It is not a dependency bundle and not a mirror of third-party assets.

## Permanent objective

Maximize **reference coverage without new primitives** while preserving:

- authorship and the KODEX canon;
- legal provenance and cultural authorization;
- small production runtimes;
- mobile, poster and reduced-motion fallbacks;
- reproducible decisions available to every agent.

## Required read order for agents

1. `docs/AGENT-RESOURCE-GUIDE.md`
2. `assets/capability-router.json`
3. `assets/reference-map.json`
4. `assets/resource-catalog.json`
5. `assets/registry.json` before using any external file

## Definition of covered

A visual reference is covered when an agent can produce a credible prototype
from existing families and recipes while changing copy, data, palette and
licensed assets independently. “Covered” does not mean visually copied.

## Coverage KPI

For each new batch of references, record:

- total references;
- references resolved with existing families;
- references requiring a new primitive;
- references blocked by rights or cultural authorization;
- median number of runtime libraries per scene;
- percentage with mobile, poster and reduced-motion paths.

Target: at least 95% resolved through composition, no more than three runtime
libraries per scene, and 100% fallback/provenance coverage. The aspirational
“99%” is measured across future batches, never claimed from one curated set.

## Change protocol

Every catalog addition must answer:

1. Which missing capability does it cover?
2. Why can existing resources not cover it adequately?
3. What is the official license evidence?
4. Is it runtime, authoring-only, pipeline-only, asset source or radar-only?
5. What is the smallest fallback?

Social references never become redistributable assets by being mapped. Cultural
symbols and ancestral material require provenance, context and authorization;
the resolver cannot waive those gates.
