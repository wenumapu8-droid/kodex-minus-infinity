Status: `EXECUTION PLAN / V0.1`

## Operating principle

Do not measure progress by the number of generated concepts. Measure progress by preserved context, verified assets, integrated modules, end-to-end paths, product evidence and qualified audience response.

## Phase A — Context and inventory

### Weeks 1–2

Objectives:

- review and merge the canonical bootstrap after human approval;
- inventory `wenu-frontend` branches and KODEX files;
- recover generated package bytes from conversation/library storage;
- record checksums, provenance, rights and privacy;
- identify duplicates, conflicts and superseded variants;
- approve the first corpus.

Deliverables:

```text
artifact registry v1
source registry v1
rights registry v1
implementation map
migration candidates
ADR-0005 corpus decision
```

Exit criteria:

- no known high-value KODEX engine is absent from the inventory;
- every verified implementation record has repository, branch, path and SHA;
- private and public material are separated.

Exit criteria:

## Weekly operating rhythm

### Monday

- update `CURRENT_STATE.md`;
- choose one primary work packet;
- identify blockers and evidence needs.

### During the week

- one branch per bounded work packet;
- additive implementation;
- actual tests and screenshots;
- registries updated with new assets or sources.

### Friday

- update changelog and handoff;
- compare work against acceptance criteria;
- identify one highest-leverage next action;
- avoid opening new concept tracks without capacity.

## Anti-drift rule

At any moment, work is paused when it cannot answer:

- which work packet owns it;
- which node/module it advances;
- which source or state controls it;
- which acceptance criterion it satisfies;
- how it contributes to the vertical slice, product or validated future module.
