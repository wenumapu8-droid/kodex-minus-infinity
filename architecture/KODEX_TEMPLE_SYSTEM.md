## Definition

The KODEX Temple System is a stateful spatial layer inside the A–Y experience. It creates the sensation of entering a living architectural chamber rather than merely opening another page.

It sits between Node Architecture and the Digital Altar:

```text
A–Y SITE / RELATION FIELD
→ NODE
→ TEMPLE SYSTEM
→ DIGITAL ALTAR
→ ORGANISM
→ ACTION
→ MEMORY
→ CONSEQUENCE
→ RETURN TO A–Y FIELD
```

The Temple System does not replace the A–Y graph, node meaning, provenance or the Organism Engine.

## Core distinction

```text
SITE ARCHITECTURE = traversal and relation topology
NODE = concept, question, sources, actions and route consequence
TEMPLE = spatial state and environmental memory
ALTAR = focused ritual-operational interaction container
ORGANISM = visual behavior / renderer
MEMORY = trace of committed interaction
```

## Creator direction

The Digital Temple should feel like an impossible visionary sanctuary characterized by:

- monumental symmetry;
- recursive architectural depth;
- nested vaults and chambers;
- radial and tessellated geometry;
- vivid spectral color;
- extremely high visual density balanced by a clear central axis;
- repeated points of warm light that can read as candles nearby and data/stars at distance;
- an altar placed on the primary axis;
- one active KODEX organism hosted by the altar;
- architecture that can mutate according to the visitor's prior route.

The experience may evoke the perceptual qualities associated with psychedelic or visionary imagery, but KODEX does not claim that such imagery proves a universal metaphysical architecture.

## Reference abstraction rule

References from Islamic geometric architecture, South Asian temple architecture, visionary art and other sacred spaces are studied only through abstractable properties such as:

- symmetry;
- recursion;
- modular repetition;
- density;
- color relationships;
- threshold sequences;
- scale;
- light;
- perception of depth.

Do not reproduce without provenance review:

- sacred figures;
- liturgical objects;
- inscriptions;
- culture-specific ritual symbols;
- deities;
- identifiable sacred narrative scenes;
- traditional patterns when their cultural status or rights are unclear.

KODEX surface language must be authored from original Ocín/KODEX symbols, fields, relations and generated geometry unless a sourced element has explicit permitted use.

## Spatial grammar

Every temple should be composable from a limited grammar rather than modeled as a unique monolithic scene.

### 1. Axis

One perceptible primary axis establishes orientation between observer, altar, organism and deeper field.

### 2. Recursive vault

Nested geometric structures suggest that the space continues beyond the viewport or physical dimensions.

### 3. Structural field

Arches, columns, ribs, cells, frames or other original KODEX modules repeat toward depth.

### 4. Light field

Repeated light points communicate energy and memory. Their reading may transform with distance:

```text
CANDLE
→ LIGHT
→ NODE
→ STAR
→ PIXEL
→ MEMORY DATUM
```

### 5. Digital Altar

The altar is the local action focus. It contains or presents the organism and explicit meaningful actions.

### 6. Organism

Exactly one high-cost real-time organism should normally dominate a temple at a time.

### 7. Memory field

Previous route decisions alter architecture, light distribution, symbols, topology or organism controls.

## Temple state model v0

Implementation proposal:

```text
DORMANT
→ AWARE
→ ACTIVE
→ MUTATED
→ RESONANT
```

These names are not locked canon yet.

### DORMANT

- mostly dark;
- incomplete architecture;
- latent symbols;
- low organism activity.

### AWARE

- presence is acknowledged;
- structural layers become legible;
- route lights begin to align.

### ACTIVE

- an explicit interaction has occurred;
- altar, organism and architecture visibly exchange state.

### MUTATED

- entered on a meaningful revisit or mutation;
- the chamber must not look identical to the first visit;
- route memory becomes materially visible.

### RESONANT

- a high-coherence state produced by accumulated context;
- a second spatial/information layer can appear;
- must never be framed as diagnosis of the visitor's mind or emotion.

## Relation to M

M remains optional and distributed.

A temple may react to a prior or contextual M interaction, but:

- M is never required to complete a temple;
- M does not score, rank or diagnose the visitor;
- a post-M temple change represents stored route state, not a claim about consciousness.

## Relation to Y

A temple is not Y.

Y remains a Return derived from the actual traversal trace. A temple can contribute state to the Return artifact, then release the visitor back to the graph.

## Performance rule

A temple should create perceptual complexity without requiring a fully modeled high-poly building.

Preferred implementation order:

1. DOM/CSS/SVG for structural framing and readable symbols;
2. instanced or procedural geometry when real 3D depth is necessary;
3. one active organism renderer;
4. low-cost atmospheric/post effects;
5. mobile quality reduction;
6. static and reduced-motion equivalents.

Never assume more geometry is better. Complexity must serve state, depth and meaning.

## Accessibility

Every temple must support:

- keyboard-operable meaningful actions;
- touch targets;
- `prefers-reduced-motion`;
- non-WebGL fallback for the core content/action path;
- readable state labels in semantic HTML;
- no interaction whose meaning is communicated solely by color or motion.
