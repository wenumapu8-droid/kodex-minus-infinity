# KODEX Factory — Production Control Plane

Status: `PROPOSED OPERATING SYSTEM / V1`

KODEX Factory turns complex creative-software production into bounded, testable, auditable work packets executed by specialized human/model stations.

The factory optimizes for **verified throughput**, not prompt count, raw code volume, generated images or agent activity.

## Core law

```text
INFINITE HORIZON
→ FINITE CONTROLLED BATCHES
→ VERIFIED OUTPUT
→ MEASURED PROCESS
→ RECIPE UPDATE
→ NEXT BATCH
```

## Authority

```text
CREATOR / DIRECTOR
→ canonical decision authority

ORCHESTRATOR
→ decomposition, routing, dependencies, cross-model dialogue,
  quality gates, evidence review and recipe evolution

SPECIALIST STATIONS
→ execute bounded packets; do not redefine canon
```

## Production cells

1. Source Intake
2. Knowledge Graph
3. Canon + Epistemic Review
4. Runtime Kernel
5. Navigation + Memory
6. Visual Specification
7. Visual Engine
8. Scene Assembly
9. Accessibility
10. Performance
11. Visual QA
12. Integration
13. Release Audit
14. Factory Learning

Each cell has explicit inputs, outputs and quality gates. Work should not move downstream while its upstream contract is incomplete.

## Files

- `FACTORY_OS.md` — industrial operating model and station definitions.
- `WORK_PACKET_SCHEMA.yaml` — canonical bounded-work contract.
- `WORKER_REGISTRY.yaml` — capability classes and routing profiles, without private machine/account details.
- `ROUTER_POLICY.md` — task decomposition and model/station routing logic.
- `FACTORY_EVENT_SCHEMA.yaml` — structured events for status/notification systems.
- `QUALITY_GATES.md` — evidence gates between production cells.
- `RECIPE_LEARNING.md` — measurable continuous-improvement loop.

## Repository boundary

This public repository stores only public-safe operating rules. Do not commit machine addresses, account identifiers, tokens, private conversations, secrets, private asset paths or other operational credentials.
