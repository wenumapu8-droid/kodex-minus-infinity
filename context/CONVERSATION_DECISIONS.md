# KODEX−∞ CONVERSATION DECISIONS

Status: `RECOVERED DECISION CONTEXT`  
These entries summarize decisions developed across conversations. They are intended to prevent loss of intent. Formal architectural decisions remain in `docs/DECISIONS.md`.

## CD-001 — KODEX is a system, not an image collection

The work must be organized as a living visual and interaction system with reusable rules, modules, code and narrative consequences.

## CD-002 — Fullscreen journey

The primary KODEX journey should use:

- one scene per viewport;
- `100svh / 100dvh` behavior;
- no vertical scroll in the core journey;
- persistent shell;
- keyboard, touch and pointer navigation;
- Browser Back/Forward;
- overlays for secondary information;
- reduced motion;
- audio opt-in.

## CD-003 — Seven canonical scene functions

```text
THRESHOLD
PROLOGUE
DESCENT
ARCHIVE
MACHINE
COSMOLOGY
RETURN
```

Scene identity must come from different functions, composition and behavior—not from recoloring the same template.

## CD-004 — First vertical slice before universe expansion

The project should prove one complete path before building every scene and portal:

```text
−∞ → THRESHOLD → OBSERVE or REMEMBER → ARCHIVE → HEART → RETURN / +∞
```

## CD-005 — Semantic convergence

All routes must converge through:

```text
MEMORY → PROVENANCE → RELATION → REFLECTION → CONTRIBUTION → RE-ENTRY
```

A return link or home redirect is insufficient.

## CD-006 — Black to white is narrative

- black/obsidian represents unresolved or compressed information;
- white represents openness, legibility and return;
- pure spectral color appears most fully after integration;
- this transformation must not be used decoratively on every page.

## CD-007 — Information must be real or classified

No arbitrary metric, timestamp, code, frequency, coordinate or signal may imply factual measurement.

Every element is:

- grounded in evidence;
- grounded in user/system state;
- explicitly atmospheric;
- or removed.

## CD-008 — Symbolic and scientific layers remain distinct

KODEX may discuss consciousness, cosmology, mythology, spiritual writing, physics and computation, but the user must be able to distinguish:

- evidence;
- interpretation;
- speculation;
- mythopoetic expression;
- synthetic simulation.

## CD-009 — Cultural material requires provenance

Ancestral and Indigenous materials require attribution, territory/community context, permission status and human review. KODEX-original neo-ancestral symbols must not be falsely presented as traditional community symbols.

## CD-010 — Heart as orientation

The heart module is central, but:

> THE HEART DOES NOT SCORE. IT ORIENTS.

It may control synthetic pulse, visual timing and optional breathing awareness. It may not invent HRV, ECG, coherence or consciousness values.

## CD-011 — Natural breathing default

Self-guided contemplative experiences use natural breathing or comfortable non-straining pacing. No forced breath retention, high-ventilation protocol or unattended intense altered-state induction.

## CD-012 — User agency

Every immersive or contemplative experience must provide visible:

- pause;
- stop;
- natural breath;
- reduced motion;
- sound off;
- ordinary orientation;
- immediate exit.

## CD-013 — DOM / SVG / WebGL division

```text
DOM   = meaning, text, controls, accessibility
SVG   = symbols, diagrams, annotations, reusable graphic language
WEBGL = organisms, depth, impossible space, feedback and transformation
CANVAS = lightweight procedural assets, exports and alpha workflows
```

## CD-014 — Motion has a limited vocabulary

Motion should encode activity, uncertainty, accumulation, divergence, relation, memory or return. Continuous animation of every label, barcode and CTA is prohibited.

Historical scene motion rule:

```text
1 protagonist movement
2 structural movements
2–4 micro-signals
```

## CD-015 — Mobile is a designed composition

Mobile is not stacked desktop UI. Test at minimum:

- 390×844;
- 412×915;
- representative desktop.

The artwork must remain dominant, CTA visible, typography unclipped and page scroll absent in the core journey.

## CD-016 — One heavy render scene at a time

- cap DPR;
- pause hidden loops;
- destroy resources on unmount;
- provide still/video fallback;
- reduced motion must remain coherent rather than broken.

## CD-017 — Reference transformation

References are analyzed into:

```text
FORMAL DNA → GRID → DENSITY → HIERARCHY → MOTION → ORIGINAL KODEX EXPRESSION
```

Do not copy source composition, palette, logo, type, symbol system or code.

## CD-018 — “Siguiente” means a new concept

During concept generation, `Siguiente` means create the next distinct concept. It does not mean revise the prior concept or generate version 2.

## CD-019 — Open source with boundaries

KODEX should expose code, sources and methods where rights permit, while protecting:

- private conversations;
- personal data;
- culturally restricted knowledge;
- unlicensed assets;
- signature marks and commercial layers;
- client-specific work.

## CD-020 — Repository as shared brain

All models must read one versioned source of truth. The dedicated repository contains canon and context; `wenu-frontend` remains the implementation source until migration is audited.

## CD-021 — Preserve, do not destructively simplify

Never delete or overwrite existing KODEX code to create a cleaner architecture. Inventory, classify, map, copy with provenance, then deprecate through explicit review.

## CD-022 — Deployment lock

No deployment without:

```text
APROBAR DEPLOY
```

## CD-023 — KODEX must become economically useful

The project should support:

- paid procedural asset packs;
- visual-engine licensing;
- commissioned living archives;
- cultural/institutional data experiences;
- generative identities;
- creative direction and context engineering;
- music, festival and entertainment systems;
- editions, prints and collector artifacts;
- an eventual KODEX Creator SDK.

The product must remain culturally valuable and not reduce itself to speculative token sales.

## CD-024 — Honest authorship

The correct professional claim is:

> I directed the system, defined constraints, iterated outputs, integrated prototypes and can explain the implementation.

Do not say the AI did everything. Do not claim engineering work that cannot be demonstrated.
