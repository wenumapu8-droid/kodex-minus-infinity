# ADR-0005 — KODEX GENESIS ARCHIVE AS THE FIRST CORPUS

Status: `ACCEPTED BY CREATOR / CORPUS CURATION IN PROGRESS`  
Date: `2026-08-06`

## Context

KODEX−∞ contains a large warehouse of visual systems, code packages, prototypes, authored Ocín works, Book material, generated references and unfinished experiments.

The first public-ready experience cannot ingest the entire warehouse. It needs one bounded corpus capable of proving the core product thesis:

```text
ONE COMMON ORIGIN
→ MEANINGFUL USER DECISIONS
→ DIFFERENT PATH CONSEQUENCES
→ OPTIONAL HEART / 0
→ RETURN / +∞
→ PATH ARTIFACT + SOURCES + RE-ENTRY
```

Candidate corpora were evaluated against provenance, rights, implementation complexity, visual fertility, external comprehension and relevance to the long-term product.

## Decision

Select **KODEX Genesis Archive** as the first vertical-slice corpus.

### Governing question

> How did Ocín's unresolved visual codes become KODEX: a living information system with memory, relation and consequence?

### Why this corpus

- it uses the creator's actual visual and computational lineage;
- it has the strongest currently available provenance;
- it can connect Ocín works, KODEX code, design systems and decisions without requiring a large external research program;
- it can produce genuinely different Memory and Machine/Artifact paths;
- it demonstrates the archive, interaction runtime, Heart and Return together;
- it creates a truthful first case study;
- it minimizes external licensing dependencies;
- it allows private conversations and mixed Drive material to remain outside the public corpus.

## Admission boundary

### Included

- verified public repository files;
- checksum-verified KODEX packages and prototypes;
- creator-approved Ocín works with direct Drive identifiers;
- selected Book fragments or images after individual privacy and rights review;
- approved decisions and rejected directions summarized without raw private conversation content;
- source-linked visual and code records;
- declared mythopoetic writing with clear authorship and truth class.

### Excluded

- raw conversation exports;
- private photo sessions;
- personal identifiers or private reflections;
- reference imagery presented as original work;
- rights-unclear cultural or religious imagery;
- unsupported scientific, biometric or spiritual claims;
- missing packages described only from memory;
- duplicate archives before checksum confirmation;
- generic generated images used to replace the creator's actual lineage.

## Corpus target

```text
15 KODEX visual/code assets
10 OCÍN works
 6 BOOK fragments or images
 3 semantic interaction primitives
 1 complete ARTIFACT ALTAR corpus
```

The selected records are tracked in:

```text
research/CORPUS_LOCK_V0_DRAFT.md
```

## First Artifact Altar candidate

### Working title

`GENESIS ALTAR / FROM MIRROR TO LIVING SYSTEM`

### Function

Show one early Ocín visual code as an authored artifact, then reveal its later relations to geometry, generative code, interaction states, memory and Return.

### Proposed material

- one approved Ocín mirror work;
- KODEX Helix Transparent;
- OBSERVE prototype;
- Visual Grammar System;
- one Archive relation view;
- one path-dependent Return transformation.

### Valid exits

```text
VIEW ORIGINAL
TRACE VISUAL GRAMMAR
OPEN GENERATIVE RULE
FOLLOW VERSION HISTORY
ENTER RELATED WORLD
RETURN WITH THE TRACE
```

The Altar does not claim that the early work had one predetermined hidden meaning. It records known context, recurring grammar, later relations and unresolved interpretation separately.

## Consequences

### Product

The first journey becomes a living self-archive rather than a generic cosmic website or a broad cultural encyclopedia.

### Design

New visual production is blocked unless the locked corpus cannot satisfy an approved node contract.

### Engineering

The runtime must ingest records with provenance, world membership, interaction roles, memory writes and Return contribution.

### Research

External cultural, scientific and art-history corpora remain future modules rather than dependencies of v0.

### Operations

Drive and Obsidian remain private working warehouses. GitHub receives reviewed metadata and approved code only.

## Exit gate

M0 is complete only when:

```text
15 KODEX RECORDS VERIFIED
+ 10 OCÍN WORKS CREATOR-REVIEWED
+ 6 BOOK ITEMS PRIVACY/RIGHTS-REVIEWED
+ 1 ARTIFACT ALTAR PACKET COMPLETE
+ SOURCE PATHS AND RIGHTS STATUS RECORDED
```

Approval of this ADR selects the corpus direction. It does not mark the corpus lock complete.

## Rejected alternatives for v0

- broad portal/threshold history across cultures;
- living information design atlas;
- holography, quantum information and geometry research experience;
- unrestricted import of the complete Drive warehouse;
- a purely generated visual journey without real authored source material.

These may return after the vertical slice proves the product thesis.

## Deployment

This decision authorizes corpus curation and implementation preparation only. It does not authorize production deployment. `APROBAR DEPLOY` remains required.
