# Contributing to KODEX−∞

KODEX−∞ accepts contributions that strengthen comprehension, provenance, accessibility, cultural responsibility and meaningful interaction.

## Before starting

Read:

1. `SKILL.md`
2. `AGENTS.md`
3. `canon/KODEX_CANON.md`
4. `canon/KODEX_EPISTEMIC_STANDARD.md`
5. `product/CURRENT_STATE.md`
6. `product/EXPERIENCE_ARCHITECTURE.md`
7. `product/QUALITY_GATES.md`

## Workflow

1. Open or select an issue.
2. Define a bounded work packet.
3. Create a branch from `main`.
4. Preserve existing files and provenance.
5. Make additive, scoped changes.
6. Run applicable checks.
7. Open a pull request using the repository template.
8. Do not merge canonical or culturally sensitive changes without human review.

## Branch naming

```text
feat/<module-or-node>
fix/<problem>
docs/<subject>
research/<corpus>
chore/<maintenance>
```

## Evidence requirements

Every factual or quantitative contribution must include:

- source;
- claim class;
- definition;
- unit and denominator when applicable;
- temporal and geographic scope;
- limitations and contradictions;
- rights status.

## Cultural materials

Do not submit restricted, sacred or community-sensitive knowledge without clear authorization. Attribution alone does not establish permission. Mark unresolved material `AUTHORIZATION_REQUIRED` and keep it out of public assets.

## Visual and interactive work

Explain:

- the question being answered;
- the meaning of every essential visual variable;
- how decisions alter the path;
- reduced-motion and keyboard behavior;
- fallback behavior;
- performance impact;
- the relationship to `RETURN / +∞`.

## Rights

Do not contribute assets, fonts, images, audio or code that you cannot legally redistribute. The repository does not yet have a general reuse license; contributions remain subject to explicit project review and future licensing decisions.

## Deployment

A merged contribution does not authorize deployment. Deployment remains blocked until the exact phrase `APROBAR DEPLOY` is provided by the project owner.
