Purpose: map the five research primitive families onto **existing canonical topology roles** without inventing new nodes, scenes or route logic.

This document does not assign meanings to unassigned B–X coordinates. It only states where a primitive family may be appropriate **if** a future admitted node has matching information and interaction requirements.

## Decision test before using a family

A future node/scene may select a family only when all answers below are explicit:

```text
1. WHAT SOURCE / WORK / QUESTION IS PRESENT?
2. WHAT DOES THE VISITOR ACTUALLY DO?
3. WHAT STATE CHANGES?
4. WHAT LATER CONSEQUENCE IS WRITTEN?
5. WHY DOES THIS MOTION FAMILY REPRESENT THAT CHANGE BETTER THAN A STATIC STATE?
6. WHAT DOES REDUCED MOTION SHOW?
7. WHAT DOES THE NON-VISUAL PATH SAY?
8. WHAT RIGHTS / CULTURAL / EPISTEMIC LIMITS APPLY?
```

If #5 has no strong answer, use a static composition.

## Candidate proof sequence after M0 gate

This is a proposed verification order, not an authorization to implement now.

### Proof 1 — Threshold state

Goal: prove that optical/raster behavior can communicate a state change while consent/orientation remain fully accessible.

Candidate family mix:

```text
B primary
A optional local layer
```

Evidence needed:

- desktop;
- mobile/touch;
- keyboard;
- reduced motion;
- non-WebGL/fallback;
- no-flash/comfort review;
- state transition recording.

### Proof 2 — Archive / Memory inspection

Goal: prove that information motion helps a visitor inspect real records/relations rather than decorate them.

Candidate family mix:

```text
D primary
E secondary
```

Evidence needed:

- admitted sample records;
- source links;
- before/selected/returned states;
- keyboard and touch inspection;
- reduced motion;
- correct filtering/relation tests.

### Proof 3 — Route-derived Return

Goal: prove that motion can synthesize actual session fragments into a legible artifact without inventing memory.

Candidate family mix:

```text
D primary
E secondary
B/C only if route state justifies them
```

Evidence needed:

- reproducible input trace;
- generated artifact compared to trace;
- Heart-visited and Heart-skipped paths;
- reduced motion;
- source/provenance access;
- no fabricated route events.
