Purpose: give the first twenty visual/motion/reference candidates one explicit disposition before any runtime implementation expands.

Allowed dispositions in this pass:

- `BLUEPRINT` — temporal/state logic is useful enough to preserve in the motion-blueprint corpus.
- `STATIC_REFERENCE_ONLY` — useful visual/compositional reference, but current evidence does not justify a dedicated motion blueprint.
- `NO_ACTION` — keep in its existing research/tool/cultural lane; do not promote into the motion blueprint corpus.

A disposition is not a rights or canon upgrade. `BLUEPRINT` means "worth preserving as abstracted behavior," not "implemented" or "approved for production."

## Runtime gate

No runtime code is authorized by this audit. Before any primitive becomes production code:

1. M0/orchestrator scope must permit it.
2. The target node/scene must name the semantic question and later consequence.
3. Provenance/rights must permit the source adaptation.
4. Reduced motion, touch, keyboard and non-visual behavior must be specified.
5. A prototype must provide browser/mobile/reduced-motion evidence before status rises above `PROTOTYPE`.

The audit intentionally rejects the assumption that every visually interesting reference should move.
